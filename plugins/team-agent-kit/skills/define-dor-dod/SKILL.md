# Условия готовности и завершения

Прочитай [правила источников](../../standards/source-policy.md), [базовый DoR/DoD](../../standards/dor-dod-baseline.md) и применимые дополнения выбранных команды/проекта по [правилам профилей](../../docs/profile-format.md). Не изобретай новый стандарт для каждой задачи.

Определи единицу оценки и этап: например, основная задача, аналитика или начало разработки. Изучи описание, родителя, связанные требования и подзадачи в релевантном объёме. Для простого изменения исключи неприменимое с причиной; добавь специфическое условие только при явной зависимости задачи.

Выведи отдельно DoR и DoD: ID исходного пункта, применимое условие, ожидаемое подтверждение. Когда пользователь просит только сформировать условия, укажи «условия сформированы, выполнение не проверено». Не отмечай пункты выполненными потому, что они присутствуют в тексте задачи.

Если запрошена оценка и есть материалы, для каждого применимого пункта добавь статус «подтверждено / не выполнено / нет данных / неприменимо» и точное доказательство либо причину. Итог для выбранной единицы: «готово», «не готово» (есть невыполненные обязательные условия), «недостаточно данных» (подтверждения отсутствуют). При сочетании двух последних перечисли и известные блокеры, и недостающие данные. Не выводи готовность разработки из готовности аналитики.

DoR проверяет достаточность подготовки, DoD — завершение работы. Проверяемое поведение продукта остаётся в функциональных требованиях/приёмке; в DoD фиксируется выполнение проверки и передача результата. При недостающих данных сформулируй точные вопросы и влияние, продолжая независимую часть.

По умолчанию верни локальный чек-лист или ответ. Этот скилл не меняет стандарт команды или источники автоматически.
