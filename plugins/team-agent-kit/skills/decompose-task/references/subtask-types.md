# Категории работ

Это категории библиотеки. Точные названия и ID типов трекера берутся из выбранного профиля и подтверждаются метаданными проекта перед записью.

| ID | Категория | Основание выделить работу | Результат |
| --- | --- | --- | --- |
| development | Разработка | Нужно изменить поведение системы | Реализованное изменение; обычная подзадача разработки, точный тип задаёт профиль проекта |
| design | Дизайн | Нужны решения взаимодействия/представления, которых ещё нет | Макет или описание состояний и поведения с согласованием |
| analysis | Аналитика | Есть конкретная неопределённость, влияющая на реализацию | Решение, модель поведения, согласованный контракт или иной обозначенный артефакт |
| testing | Тестирование | Проверка имеет самостоятельный объём/результат, например межсистемный сценарий | Результат проверки с покрытием и найденными дефектами |
| subbug | Обнаруженный дефект | Есть факт расхождения с подтверждённым ожиданием | Устранённый дефект и проверка воспроизведения |

Дизайн и тестирование не обязательны для каждого изменения. Проверка простого изменения может входить в задачу разработки. Неизвестное требование не считается дефектом.

Для категории `subbug` укажи среду/версию, предусловия и обезличенные данные, шаги и частоту воспроизведения (если известна), фактический результат, ожидаемый результат со ссылкой на требование, доказательство и влияние. Не придумывай шаги, которых источник не содержит. При неполном воспроизведении оставь вопросы и статус «не готово к исправлению»; подготовка диагностической работы возможна с явным результатом.
