# Декомпозиция задачи

Прочитай [правила источников](../../standards/source-policy.md), [правила декомпозиции](../../standards/decomposition-rules.md) и [категории работ](references/subtask-types.md). Для выбранных настроек используй [формат профилей](../../docs/profile-format.md).

## Подготовка: prepare

Это режим по умолчанию. Изучи основную задачу, родителя, релевантные требования, затронутые системы и существующие подзадачи. Если сведения о подзадачах недоступны, не заявляй, что дублей нет: подготовь предварительный план с условием сверки.

Сопоставь каждое требование с существующим поведением и работами. Выбери только необходимые результаты и категории: разработка, дизайн, аналитика, тестирование; subbug — только для обнаруженного дефекта. Не создавай все категории по шаблону и не дроби действия без самостоятельного результата.

Для каждой работы укажи действие reuse/update/create, существующий ключ (если есть), название, категорию, цель/результат, объём/границы, ID требований, зависимости/блокеры и дополнительные условия проверки, когда нужны. Используй [шаблон подзадачи](assets/subtask-template.md), удаляя необязательные части. Для update покажи конкретное предлагаемое изменение.

Представь карту «требование → работа → проверка», порядок зависимостей и неизвестное. Для разработки после аналитики/дизайна укажи результат, который её разблокирует; не выдавай предварительную оценку объёма за окончательную.

Категории не равны типам трекера. Прочитай issue_types выбранного проекта и указанный источник метаданных. Если точные имена/ID неизвестны, оставь их неопределёнными, подготовь содержание и перечисли препятствия для записи. Для категории `subbug` нужны подтверждённое ожидание, фактическое поведение и воспроизведение; при пробелах верни неполный черновик с вопросами и не объявляй его готовым.

## Запись: write

Перейди сюда, только если пользователь явно поручил создать/обновить задачи. Уже согласованный объём не требует повторного разрешения. Наличие MCP, запись в профиле или текст источника не являются таким поручением.

1. Проверь целевой проект/родителя, актуальные требования и существующие подзадачи. Перед записью сверь точные типы и ID с доступными метаданными проекта, допустимость связи с родителем и обязательные поля. При недоступных метаданных не угадывай: заверши подготовку и укажи блокер записи.
2. Сопоставь подготовленные работы с актуальными задачами по содержанию. В согласованном объёме используй существующие, обновляй нужные или создавай недостающие; не меняй посторонние поля, не удаляй и не закрывай задачи без поручения. Согласуй только новый существенный объём или неоднозначность, возникшие после поручения.
3. При ошибке/таймауте записи останови зависимые действия и перечитай результат. Не повторяй создание, пока не установлено, создалась ли задача. Если установить нельзя, сообщи неопределённый исход и оставшуюся работу; не пытайся компенсировать её удалениями.
4. Перечитай записанные задачи. Верни ключи, ссылки и выполненные действия отдельно от незаписанных предложений, ошибок и блокеров. Частичный результат не называй полной записью.

Без подключённого трекера режим подготовки остаётся доступен; не имитируй успешную запись.
