# Фильтр открытых заявок

Синтетический пример. Контекст: `example-team` / `example-project`, роль `business-analyst`, скилл `describe-task`, черновик.

## Цель

Помочь оператору сосредоточиться на открытых заявках в существующем списке.

## Функциональные требования

- FR-1: оператор может выбрать статус «Открыта» и получить только видимые ему заявки этого статуса.
- FR-2: после сброса фильтра оператор видит все доступные ему заявки независимо от статуса.

## Границы

Используется существующий компонент фильтра и готовое состояние пустого списка. Правила доступа не меняются; сохранение фильтра между сеансами не входит в объём. Отдельный дизайн не требуется.

## Источники

[request-list-baseline, версия 1](../profiles/projects/example-project/sources.md), статус `approved` только внутри учебного кейса, разделы «Контекст» и «Требования: фильтр». Родитель отсутствует, существующие подзадачи отсутствуют по входу S1. Открытых вопросов по функциональности нет; метаданные трекера не предоставлены.

User story, отдельные сценарии и критерии приёмки опущены: FR уже однозначны и проверяемы.
