# Декомпозиция фильтра заявок

Синтетический пример S1. Контекст: `example-team` / `example-project`, роль `system-analyst`, скилл `decompose-task`, режим `prepare`.

Вход: [описание задачи](task-description.md) и [исходные требования](../profiles/projects/example-project/sources.md), согласованные для учебного кейса. Родителя и существующих подзадач нет по условиям S1. Это проект работ, задачи в трекере не создавались.

## W1: добавить фильтрацию открытых заявок и сброс

- Действие: `create`; категория: `development`.
- Тип трекера и ID: не определены; метаданные не предоставлены.
- Цель/результат: оператор отбирает открытые заявки и возвращается к полному доступному списку.
- Объём: реализовать FR-1 и FR-2 через существующий компонент и добавить проверку этих действий.
- Границы: не менять доступ и не сохранять фильтр между сеансами.
- Связь с требованиями: FR-1, FR-2.
- Зависимости/блокеры: содержательных зависимостей в учебном входе нет. Запись блокируют отсутствие целевого трекера/родителя и метаданных типов.
- Проверка: набор содержит доступные открытые и закрытые заявки и недоступную открытую заявку. После выбора видны только доступные открытые, после сброса — все доступные; недоступная заявка не появляется.
