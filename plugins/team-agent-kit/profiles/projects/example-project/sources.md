# Источники учебного проекта списка заявок

Синтетический источник `request-list-baseline`, версия 1. Внутри учебных сценариев правила ниже считаются согласованными. Это не реальные клиентские данные и не сведения о действующем продукте.

## Контекст

Оператор работает со списком заявок. Текущая таблица, подписи элементов и состояния пустого результата определены в учебной базовой версии. Для добавления фильтра используется существующий компонент; отдельный дизайн не нужен. Базовая версия уже ограничивает видимость заявок областью доступа оператора.

## Требования: фильтр

- FR-1: оператор может выбрать статус «Открыта» и получить только видимые ему заявки этого статуса.
- FR-2: после сброса фильтра оператор видит все доступные ему заявки независимо от статуса.

Изменение не затрагивает правила доступа и не сохраняет фильтр между сеансами. Подробный пример: [описание](../../../examples/task-description.md).

## Метаданные трекера

Не предоставлены. Названия и ID типов не определены. Файл `issue-types.yaml` содержит пустые значения для последующего заполнения из метаданных целевого проекта, а не предполагаемые ID.

Другие учебные случаи, включая SLA, конфликт источников и дефект, задаются независимо в [сценариях](../../../checks/scenarios.md); их требования не дополняют фильтр автоматически.
