# Публичный репозиторий и GitHub Pages

Проект опубликован в [Manuchehr1411/team-agent-kit](https://github.com/Manuchehr1411/team-agent-kit), Issues включены. Сайт GitHub Pages опубликован 2026-10-19: [успешный workflow](https://github.com/Manuchehr1411/team-agent-kit/actions/runs/39275909151). После деплоя все четыре страницы проверены без авторизации: HTTP 200, ожидаемое содержание присутствует.

## Подготовленные файлы

- `website/content/` — главная страница, установка, обновления, поддержка, privacy policy и terms.
- [website/site.json](../website/site.json) — собственная конфигурация сборки сайта; не конфигурация Codex, ChatGPT или GitHub.
- [build_website.py](../scripts/build_website.py) — сборка без сторонних зависимостей.
- [.github/workflows/pages.yml](../.github/workflows/pages.yml) — workflow GitHub Pages с ручным запуском.

Сайт не является интерфейсом оркестрации агентов. Он объясняет библиотеку, ведёт в репозиторий и содержит публичные документы проекта. В нём нет форм, скриптов, аналитики или API, принимающего пользовательские задачи.

Имя издателя взято как публичный логин владельца указанного репозитория — Manuchehr1411. Это не заявление о юридическом имени или подтверждённой личности издателя OpenAI. Если на сайте нужно другое публичное имя, его следует указать в site.json. Поддержка направлена в проверенные включённые GitHub Issues; отдельный email не выдуман.

Версия в шапке инструкций и подвале читается из packaging/plugin.json. Страницы install и updates дают команды установки, обновления и проверки версии и ссылки на архив и SHA-256 в GitHub Release. Это справочные страницы: сайт сам не устанавливает пакет на компьютер и не меняет аккаунты пользователей.

## Проверка и локальный просмотр

```text
python scripts/build_website.py
python checks/validate_website.py
python -m http.server 8847 --bind 127.0.0.1 --directory dist/website
```

После запуска сервера открой локальный адрес `http://127.0.0.1:8847/`. В профиле с RTK добавь `rtk proxy` перед командами. Исходные фрагменты страниц находятся в website/content, общий стиль — в website/assets; сгенерированный dist/website вручную не редактируется.

Тексты privacy и terms подготовлены для просмотра владельцем. Перед размещением сверь имя, контакт и фактическую обработку данных, при необходимости отредактируй страницы. Сборка проверяет файлы и ссылки; она не подтверждает правовую применимость текстов и не публикует сайт.

Тексты описывают текущую статическую реализацию: GitHub обслуживает сайт и обрабатывает технические данные; поддержка ведётся публично через Issues; собственный backend и телеметрия не поставляются. Они требуют обновления при изменении этой модели. Для файлов выбрана [лицензия MIT](../LICENSE); [пояснение её применения](licensing.md).

## Последующие обновления сайта

1. После изменения страниц выполни локальную сборку и проверки, затем commit и push. Не добавляй work/, локальные секреты и результаты dist/ в Git.
2. Источник Pages уже настроен как **GitHub Actions**. При переносе в другой репозиторий выбери его в **Settings → Pages → Build and deployment → Source** и обнови site.json.
3. Запусти из вкладки **Actions** workflow «Публикация сайта GitHub Pages», выбрав основную ветку.
4. Дождись успешного deploy и открой опубликованные страницы без авторизации.

Workflow запускается только вручную и допускает деплой из основной ветки. Он загружает только dist/website; содержимое всего репозитория на сайт не выкладывается. Указанный здесь процесс соответствует [настройке Pages](https://docs.github.com/en/get-started/start-your-journey/deploying-your-website-automatically) и [официальным действиям публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). Отправка коммитов в репозиторий сама по себе не запускает публикацию сайта.
