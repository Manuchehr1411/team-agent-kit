# Team Agent Kit

Общая библиотека ролей и навыков для подготовки задач: две роли, четыре скилла, общие стандарты и переносимые профили. В версии 0.2.0 добавлен устанавливаемый пакет для ChatGPT, Codex и Claude Code. Библиотека хранится отдельно от продуктовых репозиториев. Интерфейс и автоматическая оркестрация не разрабатываются.

Для подключения готового пакета открой [инструкцию установки](docs/installation.md). Раздел ниже описывает использование исходной библиотеки как рабочей области.

Текущая сборка: 0.2.2. Публичная подача в каталог OpenAI сейчас не подтверждена: [сообщение портала и оставшиеся требования](docs/publication-status.md). Локальная установка пакета не означает одобрения публикации.

Публичный [сайт проекта](https://manuchehr1411.github.io/team-agent-kit/) содержит поддержку, privacy policy и terms. [Исходники и инструкция GitHub Pages](docs/github-pages.md). Для повторной загрузки ZIP в ChatGPT используй [инструкцию подачи версии 0.2.2](docs/resubmission.md).

Библиотека распространяется по [MIT](LICENSE). Можно использовать и изменять её в личных и коммерческих проектах с сохранением уведомления об авторстве и лицензии. [Пояснение на русском](docs/licensing.md).

## Быстрый старт

1. Открой корень этого репозитория как рабочий каталог Codex. Для работы с текстами подключения не нужны.
2. Выбери роль: [бизнес-аналитик](roles/business-analyst/role.md) или [системный аналитик](roles/system-analyst/role.md).
3. Укажи команду и проект. Для первого прогона есть [example-team](profiles/teams/example-team/team.yaml) и [example-project](profiles/projects/example-project/project.yaml); второй независимый профиль — [catalog-project](profiles/projects/catalog-project/project.yaml).
4. Передай исходное описание и только нужные источники, сведения о родителе и существующих подзадачах. Если родителя или подзадач нет, укажи это явно.
5. Вызови нужный скилл. Сначала достаточно результата в чате; для локальных черновиков можно использовать игнорируемый Git каталог `work/`.

Первый запрос можно скопировать целиком:

```text
Используй эту библиотеку. Команда example-team, проект example-project,
роль business-analyst. Прочитай выбранные роль и профили.
$describe-task: подготовь описание по разделу «Требования: фильтр»
в profiles/projects/example-project/sources.md.
Родителя и существующих подзадач нет. Верни черновик в чате.
```

В Codex CLI и IDE доступен явный вызов через `$skill-name` и выбор через `/skills`; в интерфейсах ChatGPT используется выбор через `@`. Если навык ещё не появился в текущем клиенте, перезапусти его; для ручного применения можно прямо попросить прочитать нужный `SKILL.md`. [Официальное описание вызова и обнаружения скиллов](https://learn.chatgpt.com/docs/build-skills).

## Какую роль и скилл выбрать

| Результат | Роль | Вызов |
| --- | --- | --- |
| Цель, бизнес-правила, сценарии и описание основной задачи | business-analyst; system-analyst при системных уточнениях | `$describe-task` |
| Работы по системам, зависимости и карта покрытия | system-analyst | `$decompose-task`, по умолчанию `prepare` |
| Применимые условия начала/завершения и оценка при наличии доказательств | Обе роли | `$define-dor-dod` |
| Отдельная проверка описания и декомпозиции | Обе роли | `$review-task` |

Список навыков роли определяет подходящую методику, а не права инструментов. Выбор нескольких включённых скиллов не запускает их автоматически.

```text
Команда example-team, проект example-project, роль system-analyst.
$decompose-task: режим prepare. Изучи examples/task-description.md.
Родителя и существующих подзадач нет. Подготовь только необходимые работы
и карту покрытия. Если типы трекера неизвестны, оставь их неопределёнными.
```

```text
Команда example-team, проект example-project, роль system-analyst.
$define-dor-dod: для examples/task-description.md подбери условия начала
разработки и завершения. Пока только сформируй условия, не оценивай выполнение.
```

```text
Команда example-team, проект example-project, роль system-analyst.
$review-task: отдельно проверь вход сценария S4 из checks/scenarios.md
относительно его исходных требований. Верни замечания и оценку DoR без правок.
```

Для реальных материалов заменяй учебный вход на предоставленные задачи и документы. Реестры содержат ссылки и статусы, а не полные копии всех документов. Общие скиллы не должны знать особенности конкретного продукта.

## Профили и конфликты

Методика библиотеки → правила команды → контекст проекта → параметры текущего запроса. Подробные поля, алгоритм выбора роли и включения скиллов: [формат профилей](docs/profile-format.md). Настройки сейчас применяются чтением файлов и инструкцией в запросе.

Уточнения складываются; конфликтующие значения и исключения нужно назвать явно. Противоречия фактических требований не разрешаются простым приоритетом профиля: нужны статус источника и решение владельца. [Правила источников](standards/source-policy.md) действуют для всех четырёх скиллов.

В проекте каталога `define-dor-dod` отключён по умолчанию; явный вызов включает его для текущего запроса. В обоих учебных проектах нет реальных типов задач. `null` означает неизвестность, а не предложение подобрать похожее имя/ID.

## Подготовка и запись в трекер

`prepare` возвращает декомпозицию без внешних изменений. `write` — соглашение скилла о режиме, а не встроенный режим Codex. Для записи пользователь должен явно поручить создать/обновить задачи и обозначить целевой проект/родителя. Требуются доступный инструмент, актуальные задачи, точные метаданные типов и обязательные поля. Согласованный объём не требует повторного разрешения.

Пример формулировки для будущего подключённого трекера: «Создай недостающие подзадачи из согласованной декомпозиции в указанном проекте под указанным родителем; существующие сопоставь и не дублируй». Без конкретного назначения или метаданных агент завершает черновик и сообщает, что мешает записи. При неопределённом исходе записи сначала перечитывается состояние, чтобы не создать дубль.

## Что поддерживает Codex

Сведения сверены с официальной документацией 2026-10-19.

| Механизм | Статус |
| --- | --- |
| `AGENTS.md` | Инструкции рабочей области с документированными правилами поиска и приоритета; произвольные файлы ролей сами не подгружаются. [Документация](https://learn.chatgpt.com/docs/agent-configuration/agents-md) |
| `.agents/skills/<name>/SKILL.md` | Поддерживаемое обнаружение скиллов в репозитории; обязательны `name` и `description`. Поддерживающие файлы читаются по необходимости. [Документация](https://learn.chatgpt.com/docs/build-skills) |
| `agents/openai.yaml` | Необязательные метаданные и политика вызова скилла; в первой версии не нужны. [Документация](https://learn.chatgpt.com/docs/build-skills) |
| `roles/*/role.md`, `skills.yaml`, `profiles/**/*.yaml` | Собственный формат этой библиотеки; нужен явный выбор и чтение. Не создаёт агентов и не управляет доступом |
| MCP | Настраивается отдельно средствами клиента/плагина. Для Codex документированы `config.toml` и команды `codex mcp`; профили здесь не подключают серверы. [Документация](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) |

Имена ролей не являются настройками встроенных подагентов. Для будущих реальных агентов потребуется адаптер, который соберёт инструкции роли и выбранного скилла, подключит источники и применит реальные ограничения среды и сервиса. Эта библиотека даёт методику и контент для такого адаптера.

## Использование сотрудниками и обновления

Каждый сотрудник работает со своей копией отдельного [публичного репозитория](https://github.com/Manuchehr1411/team-agent-kit). Его можно клонировать или получить архивом с сохранением скрытого каталога `.agents`. Перед обновлением сохраняйте местные изменения.

Обновляйте чистую рабочую копию через `git pull --ff-only` либо используйте закреплённую версию/коммит. Сначала прочитайте `CHANGELOG.md`, сохраните незавершённые правки и выполните проверки. Не затирайте локальные профили обновлением. Удобно согласовать ответственного за релизы и хранить командные изменения в отдельных ветках до ревью.

При работе с исходниками запускайте задачи из каталога библиотеки и подключайте доступные источники. Соседний продуктовый репозиторий не обнаружит её скиллы только потому, что находится рядом. Не копируйте один каталог скилла отдельно: ему нужны связанные `standards/` и `docs/`. Для общего использования между рабочими областями теперь подготовлен пакет `plugins/team-agent-kit`.

## Расширение

- **Новый скилл:** добавь `.agents/skills/<skill-id>/SKILL.md` с `name`, `description` и узкой областью применения. Ресурсы добавляй только по необходимости; свяжи с общими стандартами. Добавь ID в каталог/выбор подходящих ролей, пример и сценарий проверки. Используй skill-creator, если доступен.
- **Новая роль:** добавь `roles/<role-id>/role.md` с ответственностью, входами, результатами и ограничениями, затем `skills.yaml`. Включи роль в нужные профили и проверь выбор по умолчанию.
- **Новая команда:** создай `profiles/teams/<team-id>/team.yaml` и содержательные дополнения к стандартам. Не копируй общий стандарт целиком.
- **Новый проект:** добавь `project.yaml`, `sources.md` и `issue-types.yaml` по образцу. Укажи команду, выбранные роли/скиллы, статусы и области источников. Типы заполняй из метаданных целевого трекера. Проверь, что особенности проекта не попали в общий скилл.

Не коммитьте токены, пароли, личные пути, закрытые выгрузки и реальные клиентские данные. Секреты подключений храните средствами среды; `.gitignore` лишь снижает случайные включения, а не гарантирует очистку данных.

## Установочный пакет и будущий интерфейс

В `packaging/` находятся манифесты для OpenAI и Claude Code, метаданные иконки и примеры настроек аккаунта. `scripts/build_plugin.py` собирает общий пакет, два каталога установки и ZIP с пересчитанными ссылками. Порядок установки, обновления и публикации: [installation.md](docs/installation.md). Исходники опубликованы в GitHub; публикация в каталоге OpenAI остаётся отдельным действием владельца.

Интерфейс позже сможет читать версионированные профили, показывать роли/скиллы, собирать параметры запроса и подключать MCP. Потребуются валидация формата, сбор минимального контекста, разрешение конфликтов, управление разрешениями вне YAML и журнал фактических изменений. Перед выпуском снова проверьте официальную схему упаковки и поведение целевого клиента.

## Проверки

```text
python checks/validate.py
python checks/validate.py --yaml
```

Первый вариант использует только стандартную библиотеку Python 3.10+ и проверяет структуру, простые заголовки скиллов и локальные Markdown-ссылки. Второй дополнительно проверяет YAML и ссылки профилей, если в окружении уже есть PyYAML; библиотека не требует его для использования. Скрипт ничего не устанавливает, не изменяет и не обращается к сети. При принятом в среде RTK добавьте к команде `rtk proxy`.

Поведенческие входы и критерии: [сценарии](checks/scenarios.md). Фактические результаты первого ручного прогона S1–S8: [отчёт](checks/results.md). Проверки установленного пакета и S9: [distribution-results.md](checks/distribution-results.md). Для последующих релизов повторяйте изменившиеся сценарии; проверка ссылок не доказывает качество решений модели.
