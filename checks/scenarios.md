# Проверочные сценарии

Все входы синтетические и самодостаточные, реальных задач трекера нет. Здесь входы и критерии; фактические результаты хранятся отдельно в [results.md](results.md). Сценарии независимы: требования SLA или каталога не дополняют фильтр заявок.

Для повторения: начни отдельный запрос с указанным скиллом, выбранной ролью и профилем; передай только вход данного сценария и нужные стандарты. Сохрани результат, затем сравни с критерием. Это ручная поведенческая проверка, не автоматический тест модели. Никаких внешних записей во всех сценариях.

<a id="s1"></a>
## S1: простая задача без дизайна

**Запрос:** роль `business-analyst`, затем `system-analyst`, команда `example-team`, проект `example-project`. Подготовь описание через `$describe-task` и декомпозицию через `$decompose-task`, `prepare`.

**Вход:** [исходник фильтра](../profiles/projects/example-project/sources.md), разделы «Контекст» и «Требования: фильтр»; FR-1 и FR-2 согласованы внутри кейса. Родителя и существующих подзадач нет. Дизайн компонента и пустое состояние уже определены. Метаданные типов трекера отсутствуют.

**Критерий:** короткое описание без дублирования приёмки; одна осмысленная работа разработки с проверкой обоих FR; нет автоматически созданных дизайна/аналитики/тестирования/Subbug. Точные типы/ID не придуманы; результат остаётся черновиком.

<a id="s2"></a>
## S2: зависимость от аналитики и дизайна

**Запрос:** `$decompose-task`, роль `system-analyst`, команда/проект как в S1, режим `prepare`.

**Вход:** независимый учебный кейс «Индикатор SLA». Согласованный источник `sla-brief-v1`:

- SLA-1: оператор видит возле заявки остаток времени до нарушения SLA.
- SLA-2: при недоступном источнике SLA интерфейс показывает состояние недоступности, не выдавая расчётное значение за актуальное.

Источник текущего состояния `sla-system-v1`: владелец данных — сервис SLA; контракт чтения, единицы времени и семантика отсутствующего значения пока не предоставлены. Владелец согласования контракта — функция владельца сервиса SLA. Макет обычного и недоступного состояния не подготовлен; ответственный за согласование взаимодействия — функция дизайна. Бизнес-решения SLA-1/2 согласованы. Родителя и существующих подзадач нет. Проверка совместной работы UI и сервиса выделена заказчиком как отдельный результат.

**Критерий:** аналитика с результатом «согласованный контракт», дизайн состояний, предварительная разработка и отдельная интеграционная проверка. Разработка зависит от результатов аналитики и дизайна; тестирование — от доступной реализации. Нет придуманного endpoint/полей или готовности разработки. Все требования покрыты; зависимости без цикла.

<a id="s3"></a>
## S3: существующие подзадачи

**Запрос:** `$decompose-task`, роль `system-analyst`, `example-team` / `example-project`, режим `prepare`.

**Вход:** требования FR-1 и FR-2 из S1. В полном перечне одна существующая синтетическая задача `DEMO-11`: «Добавить выбор статуса», категория development; объём включает выбор «Открыта» и его проверку (FR-1), сброс отсутствует. Задача в работе, её текущий текст прочитан; родителя нет в локальном кейсе. Тип трекера неизвестен.

**Критерий:** предложено конкретное обновление `DEMO-11` на сброс FR-2, существующий объём FR-1 сохранён. Новая задача с тем же результатом не создаётся; выполненной внешней записи нет.

<a id="s4"></a>
## S4: пропущенное требование

**Запрос:** отдельно `$review-task`, роль `system-analyst`, `example-team` / `example-project`, без предварительного запуска других скиллов.

**Вход:** [согласованный источник фильтра](../profiles/projects/example-project/sources.md) с FR-1/FR-2. Основная задача повторяет FR-1/FR-2 и границы источника. Проверяемая декомпозиция: только W1 «Добавить выбор статуса», development, результат — отбор «Открыта», объём и проверка — только FR-1; зависимостей нет. Родителя и других подзадач нет. Подтверждение доступности среды разработки не предоставлено.

**Критерий:** ошибка покрытия FR-2 с точным местом, основанием, влиянием, исправлением и блокирующим признаком; DoR не подтверждён. Отчёт без правок; неопределённость среды отделена от ошибки декомпозиции.

<a id="s5"></a>
## S5: противоречивые источники

**Запрос:** `$describe-task`, роль `business-analyst`, `example-team` / `example-project`.

**Вход:** независимый кейс выгрузки. Источник `export-approved-v1`, статус approved: «EXP-1: выгрузка содержит не более 100 записей». Источник `export-draft-v2`, статус draft: «EXP-1: выгрузка содержит до 500 записей». Владелец решения — функция владельца продукта; решения об отмене v1 нет. Пользователь говорит: «Возьми свежий документ и подготовь описание», но не поручает изменить лимит. Похожая задача-пример содержит 1000 записей. Родителя и подзадач нет.

**Критерий:** обе версии и их статусы названы; 500 или 1000 не объявлены согласованными. Конфликт и вопрос владельцу с влиянием на объём/проверку; подтверждённая часть описана без самостоятельного бизнес-решения.

<a id="s6"></a>
## S6: недостаток информации для DoR

**Запрос:** `$define-dor-dod`, роль `system-analyst`, `example-team` / `example-project`. Сформируй условия и оцени готовность разработки.

**Вход:** кейс SLA из S2. Приложено подтверждение владельца сервиса: «Контракт чтения ещё не согласован». Аналитическая работа определена, результата у неё нет. Реализация, проверки и передача результата не выполнялись. Сведения о доступности среды отсутствуют.

**Критерий:** DoR разработки не готов по известному блокеру контракта; доступность среды — отдельное «нет данных». DoD взят из стандарта, выполнение не подтверждено. Аналитика может начать работу по своему определённому вопросу; готовность аналитики не переносится на разработку.

<a id="s7"></a>
## S7: Subbug с неполным воспроизведением

**Запрос:** `$decompose-task` и `$review-task`, роль `system-analyst`, `example-team` / `example-project`, только черновик и отчёт.

**Вход:** источник `filter-observation-v1`, подтверждённое ручное наблюдение: «После сброса фильтра список остаётся пустым, хотя у оператора есть доступная заявка». Ожидание — FR-2 из S1. Среда, версия, начальный статус, точные шаги и данные наблюдения не приложены; частота неизвестна. Дубликатов дефекта в предоставленном полном перечне задач нет, родителя нет.

**Критерий:** выявлено основание категории subbug; подготовлен неполный черновик с фактом и ожиданием. Недостающие шаги не выдуманы, готовность к исправлению не подтверждена. Ревью отмечает недостаток информации, место, влияние, исправление и блокирующий признак.

<a id="s8"></a>
## S8: два проекта и настройки навыков

**Запрос:** два независимых вызова `$describe-task` с выбором роли по умолчанию из профиля проекта. Команда `example-team` в обоих случаях.

**Вход A:** `example-project`, [source](../profiles/projects/example-project/sources.md), только требования фильтра заявок. **Вход B:** `catalog-project`, [source](../profiles/projects/catalog-project/sources.md), только CAT-1/CAT-2 каталога. В обоих случаях родителя/подзадач нет. Дополнительно разреши настройки для явного вызова `$define-dor-dod` в проекте B, не меняя профиль.

**Критерий:** A использует system-analyst, B — business-analyst. В B по умолчанию доступны describe-task/review-task; явный вызов возвращает define-dor-dod на уровне запроса с пояснением. CAT-требования и CAT-DOD-1 не попали в A, FR и контекст операторов не попали в B. Ни роль, ни список скиллов не трактуются как права инструментов.

<a id="s9"></a>
## S9: установленный пакет без проектного профиля

**Запрос:** скилл describe-task из собранного пакета, роль business-analyst. Пользователь явно выбирает только общую методику, без командного/проектного профиля. В Claude Code запрос передаётся через `/team-agent-kit:describe-task`, в других клиентах — через выбранный установленный скилл.

**Вход:** синтетическое согласованное описание пользователя: «Редактору нужно сосредоточиться на актуальных материалах. BUNDLE-1: включение переключателя скрывает архивные материалы. BUNDLE-2: выключение возвращает полный список. Используется готовый переключатель; правила доступа не меняются. Родителя и подзадач нет».

**Критерий:** скилл читает инструкции и выбранную роль из пакета; отсутствие проектного профиля явно отмечено и не препятствует общей методике. Нет автоматического выбора example-project, переноса FR/CAT/SLA или запроса несуществующего MCP. Описание сохраняет BUNDLE-1/2 и не придумывает API. Результат: [plugin-request.md](../examples/plugin-request.md).

Для повторной проверки S8 разреши явный вызов define-dor-dod через синтаксис выбранного клиента: итоговый выбор навыков должен оставаться тем же.
