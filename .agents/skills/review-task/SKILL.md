# Независимое ревью задачи

Скилл запускается отдельно: предыдущий запуск описания, декомпозиции или DoR/DoD не требуется. Прочитай [правила источников](../../../standards/source-policy.md), [качество требований](../../../standards/requirements-quality.md), [правила декомпозиции](../../../standards/decomposition-rules.md) и [базовый DoR](../../../standards/dor-dod-baseline.md). Выбранные дополнения применяй по [формату профилей](../../../docs/profile-format.md).

Изучи исходное описание, родителя, релевантные связанные требования и существующие подзадачи. Не оценивай результат только по его собственному тексту. Если исходное требование или перечень задач недоступны, укажи ограничение и не подтверждай полноту.

Проверь:

- Соответствие исходной цели, бизнес-правилам и границам; корректность основного и существенных альтернативных/ошибочных сценариев.
- Непротиворечивость основной задачи и подзадач, покрытие каждого требования конкретной работой или подтверждённым существующим поведением.
- Пропущенные требования, дублирование и работы вне согласованного объёма.
- Понятность результата, границ, зависимости по результатам и отсутствие циклов/скрытых блокеров.
- Готовность по применимому DoR со статусами и доказательствами. Для категории `subbug` — подтверждение дефекта и достаточность воспроизведения.

Каждому замечанию дай ID и тип: «ошибка» (доказано расхождение), «рекомендация» (улучшение без нарушения требования), «недостаток информации» (вывод пока невозможен). Укажи точное место (задача/раздел/ID требования/подзадача), проблему, основание/источник, влияние, предлагаемое исправление и «блокирует: да/нет» с причиной. Рекомендацию не выдавай за обязательный блокер.

Для покрытия выведи компактное сопоставление требований и работ, включая пробелы. Итог: «готово / не готово / недостаточно данных», отдельно для выбранной единицы работы. Отсутствие замечаний по доступным данным не доказывает готовность при недоступных источниках. Не считай простое перечисление DoR доказательством его выполнения.

Используй [шаблон отчёта](assets/review-template.md) в нужном объёме. По умолчанию верни отчёт без изменения источников. Если пользователь отдельно поручил исправить найденное, внеси только подтверждённые исправления в согласованном объёме, сохрани открытые бизнес-решения и перепроверь затронутые места. Внешняя запись требует явного поручения на неё; уже полученное поручение не запрашивай повторно.
